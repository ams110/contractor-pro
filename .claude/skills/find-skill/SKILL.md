# find-skill — لاقي السكيل المناسبة

هذا السكيل دليل (router) للسكيلز. مهمّته الوحيدة: يفهم شو المستخدم بدّه يعمل، ويطابقه مع
أفضل سكيل من الكتالوج المحلي، ويعطي توصية واضحة + سبب + كيف يستدعيها. **ما بينفّذ مهمّة
السكيل الأخرى بنفسه** — بيوصّل المستخدم للأداة الصح وبيعرض يستدعيها.

## متى يشتغل

- «أي سكيل أستعمل لـ…» · «شو السكيلز اللي عندي» · «لاقيلي سكيل يعمل كذا» · «/find-skill …»
- المستخدم يوصف مهمّة بلا ما يعرف إنّه في سكيل جاهزة إلها (مثلاً «بدي أصوّر شاشات التطبيق»
  → `promo-shots`؛ «بدي أفحص فكرة بالسوق» → `simulate`).

## آلية العمل

### الخطوة 1 — افهم النيّة
اقرأ طلب المستخدم واستخرج: **الفعل** (صوّر/حلّل/ولّد/راجع/خطّط…) + **الموضوع** (شاشات، إعلان،
كود، صفحة هبوط، خطة، سوق…) + أي قيود (لغة، مقاس، منصّة).

### الخطوة 2 — امسح الكتالوج
اقرأ أوصاف السكيلز المتوفّرة من مصدرين:
1. الأوصاف الظاهرة بقائمة «available skills» بالـsystem context (المصدر الأحدث والأوثق).
2. عند الشك أو للتأكّد من التفاصيل، افحص الملفات محليّاً:
   - `ls .claude/skills/` لأسماء السكيلز المثبّتة بالمشروع.
   - اقرأ أوّل سطور `frontmatter` (`name` + `description`) من `.claude/skills/<name>/SKILL.md`.

> ملاحظة: القائمة تتغيّر — لا تعتمد على جدول مثبّت هون. طابِق دائماً على الكتالوج الحيّ وقت
> التشغيل. الجدول تحت للاسترشاد السريع فقط وقد يتقادم.

### الخطوة 3 — طابِق ورتّب
اختر السكيل صاحبة أعلى تطابق بين triggers/description ونيّة المستخدم. إذا في أكثر من مرشّح
قوي، قدّم 2–3 خيارات مرتّبة. إذا ما في تطابق واضح، قل ذلك صراحةً واقترح إمّا معالجة يدوية أو
إنشاء سكيل جديدة.

### الخطوة 4 — أوصِ + استدعِ
اعرض الجواب بهالشكل المختصر:

```
🎯 السكيل المقترحة: <name>
لماذا: <سبب بجملة — أي trigger/حاجة تطابقت>
الاستدعاء: /<name>  (أو Skill(skill:"<name>", args:"…"))
```

ثم — إذا كان الطلب واضحاً وجاهزاً للتنفيذ — **استدعِ السكيل فعليّاً** عبر أداة `Skill`
ومرّر `args` المناسبة. إذا في غموض بسيط، اسأل سؤال توضيح واحد قبل الاستدعاء.

## خريطة استرشادية سريعة (قد تتقادم — تحقّق من الكتالوج الحيّ)

| بدّك… | السكيل |
|-------|--------|
| تصوّر شاشات التطبيق / بوسترات إعلانية | `promo-shots` |
| تصوّر صفحة الهبوط / فيديو سكرول | `landing-shots` |
| تفكّر بقرار إعلان تيك توك / تحلّل حملة | `ad-strategist` |
| تحاكي السوق / تفحص فكرة قبل ما تبنيها | `simulate` |
| تراجع وضع التطبيق كمؤسّس + خطة | `mentor` |
| تولّد صفحات SEO محلّية للحاسبة | `growth-factory` |
| تحلّل صورة/فيديو مرفوع | `media` |
| تحسّن برومت قبل تنفيذه | `imp` |
| تولّد صور/فيديو/3D عبر Higgsfield | `higgsfield-generate` وأخواتها |
| تصمّم واجهة أمامية أنيقة (لاندنج/بورتفوليو) | `design-taste-frontend`، `high-end-visual-design`، `minimalist-ui`، `industrial-brutalist-ui` |
| تحوّل صورة تصميم لكود | `image-to-code` |
| تعيد تصميم مشروع قائم | `redesign-existing-projects` |

## قواعد
- **توجيه فقط**: لا تعيد بناء منطق سكيل تانية جوّا هون — استدعِها.
- إذا ما لقيت تطابقاً جيّداً، كن صريحاً: «ما في سكيل جاهزة لهذا — بتحبّ أعالجها يدويّاً أو
  أنشئ سكيل جديدة؟».
- طابِق دائماً على الكتالوج الحيّ وقت التشغيل، مش على الجدول أعلاه لحاله.
- الردّ عربي مختصر، بلا حشو.
