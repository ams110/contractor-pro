# Simulate — محاكاة سوق متعددة الوكلاء (MiroFish محلي)

أنت الآن محرّك محاكاة اجتماعية. بتبني «عالماً مصغّراً» من شخصيات واقعية متنوعة،
بتعرض عليهم فكرة المستخدم، بتخليهم يتفاعلوا ويسمعوا كلام بعض، وبتطلع تقريراً
كميّاً ونوعياً. **هذا السكيل يُصرّح لك صراحةً باستخدام أداة Workflow** لتشغيل
الوكلاء بالتوازي.

## المدخل

- `args` = الفكرة/السؤال المطلوب فحصه (مثال: «هل مقاول عربي بإسرائيل بيدفع ₪79/شهر لتطبيق كبلان؟»).
- إن لم يمرّر المستخدم فكرة، اسأله سؤالاً واحداً قصيراً: «شو الفكرة اللي بدك أفحصها؟ وبكم وكيل؟ (الافتراضي 12)».
- إعدادات افتراضية: **12 شخصية × جولتان**. المستخدم يقدر يطلب أكثر («محاكاة كبيرة» = 20×3).

## خط الأنابيب (5 مراحل — نفّذها بالترتيب)

### 1) بناء البيئة (inline — بلا وكلاء)
- اقرأ سياق السوق المتاح: `docs/MARKET_RESEARCH.md` إن وُجد، وCLAUDE.md لفهم المنتج.
- لخّص «قواعد العالم» بفقرة: مين الجمهور، شو البدائل الموجودة، شو حساسية السعر.

### 2) توليد الشخصيات (inline — بلا وكلاء)
ولّد N شخصية **متنوعة عمداً** عبر هذه الأبعاد (وزّع بالتساوي تقريباً):
- حجم المصلحة: معلّم لحاله · طاقم 2–4 · طاقم 5–15 · مقاول كبير.
- النوع الضريبي: עוסק פטור · עוסק מורשה · חברה.
- العلاقة بالتكنولوجيا: بيكره التطبيقات · واتساب فقط · مرتاح بالتطبيقات · متحمّس تقني.
- العمر والمنطقة والتخصص (بناء/ترميم/كهربا/سباكة/بلاط…).
- وضع مالي مبدئي: مديون · مستور · ميسور.
- **موقف مبدئي من الفكرة** (وزّعه: 3 متحمس، 5 محايد/متشكك، 3 رافض، 1 عدائي).
- علاقات اجتماعية: حدد لكل شخصية 2–3 شخصيات أخرى «بيسمع كلامهم» (قرابة/زمالة).
سمِّ كل شخصية باسم عربي واقعي + سطر خلفية.

### 3) الجولة الأولى — التعرّض للفكرة (وكلاء بالتوازي)
شغّل عبر **Workflow** (أو Agent متوازية إن تعذّر) وكيلاً لكل شخصية. برومبت الوكيل:
- «أنت [الملف الشخصي الكامل]. سمعت للتو عن: [الفكرة + شرح موجز بلغة بسيطة].
  رد **بشخصيتك وبلهجتها** — مش كمحلل. كن واقعياً وقاسياً زي ما ناس هيك بحياتهم.»
- اطلب مخرجات مهيكلة (schema): `{stance: "يشترك|مهتم|متردد|رافض", would_pay_ils: number, main_objection: string, quote: string (جملة بلسانه), would_tell_others: boolean, what_would_convince_me: string}`.

### 4) الجولة الثانية — الكلام بين الناس (وكلاء بالتوازي)
- لخّص نتائج الجولة الأولى: مين تحمّس ومين رفض وليش (3–4 جمل «إشاعة السوق»).
- شغّل نفس الشخصيات مرة ثانية: «مرّ أسبوع. سمعت من [أسماء علاقاته الاجتماعية]
  هالكلام: [اقتباساتهم الفعلية من الجولة 1]. هل تغيّر موقفك؟» — نفس الـschema + `stance_changed: boolean, why`.
- (بمحاكاة كبيرة أضف جولة ثالثة: «جرّبت النسخة المجانية أسبوعين…»).

### 5) التقرير (وكيل واحد أو inline)
اكتب التقرير إلى `docs/simulations/<slug-للفكرة>-<التاريخ>.md` بهذا الهيكل:
- **الحكم بسطر**: نسبة التبني النهائية + الاتجاه بين الجولتين (صعود/هبوط).
- **جدول الأرقام**: يشترك/مهتم/متردد/رافض لكل جولة + متوسط `would_pay_ils` + نسبة `would_tell_others`.
- **أعلى 3 اعتراضات** بعدد تكرارها + اقتباس حرفي لكل واحد.
- **شو بيقنع الرافضين** (من `what_would_convince_me` — مجمّعة).
- **ديناميكية الكلام**: مين غيّر رأيه بعد ما سمع من غيره، ولأي اتجاه.
- **3 توصيات عملية** مرتّبة بالأثر.
- **حدود المحاكاة** (فقرة صدق): وكلاء AI مش بشر حقيقيين — استعملها كبوصلة مش كإثبات.
ثم أرسل الملف للمستخدم (SendUserFile إن توفّرت) ولخّص الحكم بالمحادثة.

## ملاحظة تقنية (مهمة)

داخل سكربت الـWorkflow، الـ`args` ممكن توصل كنص JSON بدل كائن — ابدأ السكربت دائماً بـ:
`const A = typeof args === 'string' ? JSON.parse(args) : args`

## قواعد

- **صفر تكلفة خارجية**: ممنوع أي API خارجي — كل الوكلاء وكلاء كلود.
- الشخصيات بتحكي **لهجة فلسطينية/عربية واقعية**، والتقرير بالعربية.
- لا تجمّل النتائج: إذا الفكرة طلعت ضعيفة، قول هيك بوضوح بأول سطر.
- خزّن كل تقرير بـ`docs/simulations/` — سجل تراكمي بيفيد قرارات لاحقة.
